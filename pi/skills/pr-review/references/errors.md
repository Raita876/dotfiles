# errors: 失敗が見えるか

失敗時に利用者や呼び出し元が正しい判断をできるか追跡する。

- catch、空のハンドラ、終了コードの無視、成功値への置換、部分成功の隠蔽を調べる。
- リトライの上限、タイムアウト、キャンセル、冪等性、ロールバックが実際の呼び出し方と整合するか確認する。
- フォールバックが正当な仕様か、データ欠落や誤った成功通知を隠すだけか判断する。
- ログやエラーが原因を追跡できるか、秘密情報や個人情報を含めないかを見る。

意図された best-effort 処理を一律に不具合扱いしない。どの失敗条件で何が誤って観測されるか、上位層で処理されていないかを確かめて報告する。
