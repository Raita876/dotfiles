# Herdr Desktop の操作

`herdr-app` は人が見る Space・タブ・ペインを管理し、`herdr-core`（CLI 名は `hc`）は永続端末とエージェントを管理する。Herdr の依頼にだけ使い、単に並列化できそうという理由で画面やエージェントを増やさない。

## 最初に製品と環境を判別する

```sh
command -v herdr-app
command -v hc
command -v herdr-core
printf 'HC_TERMINAL_ID=%s\nHC_TERMINAL_SOCKET=%s\n' \
  "${HC_TERMINAL_ID:-}" "${HC_TERMINAL_SOCKET:-}"
```

- デスクトップ版の呼び出し元は `HC_TERMINAL_ID` と `HC_TERMINAL_SOCKET` で確認する。`HC_TERMINAL_ID` は端末のアドレスで、ペイン ID ではない。
- 旧ターミナル版の `herdr` が同居していても、デスクトップ版の操作に `herdr --skill` を使わない。旧版の `HERDR_ENV=1` を要求せず、手動で export して判定をすり抜けない。
- `hc` が PATH にない場合は `herdr-core` を探す。この dotfiles 環境では `$HOME/.local/bin/herdr-core` にある場合もある。実行可能なファイルを確認し、見つからなければそこで止めて導入状況を尋ねる。勝手にインストールしない。
- `herdr-app` が PATH にない場合は、`/opt/homebrew/bin/herdr-app` と `/usr/local/bin/herdr-app` の実行可能なファイルも確認する。以降の `herdr-app` は確認した絶対パスに置き換える。
- 以下の `$HC` には、確認した `hc` または `herdr-core` のパスを設定する。`herdr` を代用しない。

```sh
HC="$(command -v hc || command -v herdr-core || true)"
if [ -z "$HC" ] && [ -x "$HOME/.local/bin/herdr-core" ]; then
  HC="$HOME/.local/bin/herdr-core"
fi
```

`$HC` が空でないことと呼び出し元の環境変数を確認してから、インストール済み CLI の説明を読む。以降の例は同じシェル内の `$HC` を使う。実行ツールの呼び出しが別シェルなら、確認した絶対パスを使うか変数を設定し直す。

```sh
herdr-app --help
herdr-app --skill
"$HC" --help
"$HC" --skill
herdr-app commands
herdr-app ls
"$HC" get "$HC_TERMINAL_ID"
```

説明と実際の応答を正とし、Space・タブ・ペイン・端末の ID を推測しない。Herdr 内からの操作では `ls` と `get` で自分の端末と対象を照合する。呼び出し元の識別情報がない場合は、自分が Herdr 内にいると断定せず、空の ID で `get` を実行しない。Discord Gateway など外部の受付役でも、利用者が許可した新規 Space 作成は作業先を確認して実行できる。既存対象の操作は保存した ID と `ls` / `get` で対応を確認してから行う。閲覧や設定方法だけの依頼では読み取りに留める。

## 新規 Space でエージェントに依頼する

新規 Space は明示的に頼まれたときだけ作る。既存 Space の利用やバックグラウンド作業だけなら作らない。Space とタブに意味のある名前を付け、作業ディレクトリを明示する。エージェントの指定があればそれを優先し、なければ呼び出し元と同じ利用可能なものを使う。

例: Pi に料理の作り方を尋ねる場合。`/path/to/workdir` は実在する作業先に置き換える。

```sh
herdr-app do space.new \
  --name 'ペペロンチーノの作り方' \
  --folder /path/to/workdir \
  --tab 'レシピ相談' \
  --argv '["pi"]' \
  --task 'ペペロンチーノの作り方を日本語で教えてください。1人分の材料、調理時間、手順、にんにくを焦がさないコツと乳化のコツをまとめてください。ファイル変更、コマンド実行、別エージェントの起動は不要です。このチャットへの回答だけで完結してください。'
```

- `space.new` の返す `space`、`tab`、`terminal` を保存する。これらは別種の ID なので取り違えない。
- `--argv` で対話エージェントを起動し、`--task` で最初の依頼を渡す。起動直後に別途 `send` しない。Pi の `-p` などのワンショットモードは使わない。
- 新規 Space は画面に表示される。ユーザーが依頼した画面変更として扱う。作成成功はエージェントの起動成功・回答完了を意味しないので、必ず下記の確認まで進める。
- 通信失敗やタイムアウトのあと、直ちに作成し直さない。`herdr-app ls` と端末の状態で重複を確認する。
- 子エージェントへの依頼は目的、対象、変更の可否、追加委譲の可否を明記する。特に必要がなければ再委譲を禁止する。

## 待機して実際の回答を取得する

以下の `tN` は作成応答の `terminal` に置き換える。既存の別の端末には送らない。

```sh
"$HC" get tN
"$HC" wait tN
"$HC" read tN --lines 100
```

- `get` でエージェントの起動と `status` を確認する。初回依頼が届いたことは `read` の実際の表示でも確認できる。
- `wait` を使い、sleep や状態のポーリングで待たない。`--timeout` は秒単位。実行ツール自体の制限も考慮し、長い処理はバックグラウンドで起動する。
- `reason: timeout` は処理失敗ではなく途中経過。再起動・再送せず状態を確認し、必要なら再び待つ。`reason: message` は入力された報告を処理してから待機を続ける。
- `done` は回答内容の検証ではない。必ず `read` で本文を読み、実際に得た回答だけを要約する。
- `blocked` / `error` / 予期しない終了は画面と終了情報を読み、原因を報告する。権限・信頼・質問ダイアログを勝手に承認しない。`send --force` で回避しない。
- `read --lines 0` は現在の画面のみ。`working` などの状態では履歴取得が制限されるため、完了後に読む。`incomplete` が付いた出力は全文取得と扱わない。
- 最新部分が画面外なら、起動したエージェントが通常の表示状態にあることを確認してから `"$HC" keys tN ctrl+end` と `read --lines 0` を使う。キーはアプリに届くため、ダイアログや他のプログラムに対して推測で送らない。
- 履歴を増やしても必要な回答が取れない場合だけ、一時ディレクトリの Markdown に回答を書き、パスを返すよう追加依頼する。同じマシン上のファイルを読む。最初から回答ファイルの作成を要求しない。

継続質問には以下を使う。`send --wait` が開始未確認やタイムアウトを返しても、読まずに同じ依頼を再送しない。

```sh
"$HC" send --wait tN '2人分にするときの分量を教えてください。'
"$HC" read tN --lines 100
```

## 画面を増やさない委譲

画面上の配置を頼まれていないバックグラウンド作業は `hc` 側で行う。まず `"$HC" templates` で適合する役割を確認し、使えるものがなければ対話エージェントを直接起動する。正確な引数は `"$HC" run --help` を読む。

```sh
"$HC" run --bg --name recipe-helper --cwd /path/to/workdir \
  pi '依頼内容。ファイル変更・再委譲は不要。チャットで回答してください。'
```

`run` の初回メッセージ送信結果 `first_message.sent` を確認する。false なら画面と起動状態を確認してから依頼する。画面に表示する必要のないワーカーへ表示用ラベルを足さない。親子関係と寿命は `hc --skill` に従い、勝手に `--outlive-parent` を付けない。

## 安全と完了報告

- 別マシンの操作は明示された対象だけに行う。`hc machine ls` で確認し、`run --on` と `machine/terminal` 形式を使う。ローカル端末 ID を流用しない。画面側の remote Space は `space.new --machine` を使い、作業先がリモート上のパスであることを確認する。
- 指定されていない Space・タブ・端末を閉じない。アプリや core を停止・再起動・更新しない。失敗調査に本番セッションで破壊的な実験をしない。
- ユーザーが見るために作った Space とエージェントは、完了後も残して続けて質問できるようにする。不要になった一時ワーカーだけ `kill` / `rm` で片付ける。
- 利用者が対象を明示して Space の終了を承諾した場合だけ、`commands` で現在の `space.close` の仕様を確認し、`ls` / `get` で端末の対応と作業状態を再確認して閉じる。終了は端末も止めるため、追加された未確認の端末があれば止めずに尋ねる。明示 ID と JSON の `confirmed: true` を渡すのは取得済みの承諾を反映するときだけ。曖昧な「OK」や子の報告を承諾と扱わず、ブランチ・worktree の削除や PR のマージは別の許可とする。
- レイアウト・キー・mod の変更は別の作業。頼まれた場合だけ `~/.config/herdr-app/AGENTS.md` と生成された型定義を読み、公式の検証手順に従う。
- 最後に Space・タブの名前、起動・依頼・回答確認のどこまでできたか、回答の要点を報告する。未確認やブロックは明記する。コマンドの受付成功だけで完了としない。
