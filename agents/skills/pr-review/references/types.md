# types: データ契約と不変条件

型定義、スキーマ、データモデルが、呼び出し元と外部入力の両方で契約を守るか調べる。

- optional/null、列挙値、単位、範囲、状態遷移を利用側と突き合わせる。
- 型アサーションや広すぎる型で不正な状態が隠れていないか確認する。
- JSON、DB、HTTP などの境界では静的型だけに頼らず、実行時検証との対応を見る。
- シリアライズ、移行、既存データとの互換性、公開後の変更の影響を確認する。
- 不変条件の所有者と検証場所が明確か、複数の値が矛盾し得ないかを見る。

抽象化やクラス導入そのものは要求しない。不正な入力や状態がどの経路で通って何を壊すかを根拠にする。対象に型・スキーマの変更がなければ、無理に設計論を広げない。
