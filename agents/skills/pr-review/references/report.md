# 報告形式

## 観点別の結果（サブエージェント・単独実行で共通）

冒頭に観点、対象リビジョンと範囲、確認したファイル、未確認のファイル・理由を書く。
指摘ごとに以下を含める。

- **重大度**: P1（データ損失、権限逸脱、主要機能の破損など、優先して直すべきもの）、P2（具体的な条件で誤動作するもの）、P3（軽微だが根拠のある問題）。P0 は広範かつ即時の実害が裏づけられる例外に限る。
- **場所**: repo 相対パスと最小限の行範囲。原則として新しい側の変更行。削除のみなら旧側と明記する。
- **根拠と影響**: 差分に導入された問題、到達する条件、実際の呼び出し元・利用箇所などの証拠。事実と推測を分ける。
- **修正方針**: 最小限の提案。編集・自動修正はしない。
- **確度**: high（コード上の経路と条件を確認）、medium（具体的だが前提に未確認事項あり）。low は不具合一覧ではなく質問へ分ける。実行していない再現テストを成功扱いしない。

確定した指摘がなければ「この観点では確定した指摘なし」とする。未解決の質問、テスト未実行、その他の検証制限を別途記載する。単なる好みや一般論、既存の問題、型設計の点数付けを不具合として水増ししない。
`simplify` の提案は不具合と分離し、重大度を付けず、保持すべき振る舞いとトレードオフを書く。

## メイン agent の最終報告

1. **対象**: repo、PR URL（該当時）、base/head SHA、作業ツリーを含むか、スナップショット取得後の変更有無。
2. **指摘**: 重要度順。重複を統合し、ファイルと行、影響・根拠、修正方針、確度を簡潔に示す。
3. **簡素化の提案**: 指定された場合のみ。不具合一覧に混ぜない。
4. **実行方式と観点ごとの状況**: 利用した委譲ツールと並列数、または「単独・観点別の逐次レビュー」を記載する。code/tests/errors/comments/types/simplify の完了・非該当・未選択・失敗・未完了と理由、途中で実行方式を変えた観点を示す。確認済みと未検証の範囲を示す。
5. **検証と残課題**: テストは原則未実行であること、未解決の質問、見られなかったファイル、必要な追加検証。

「全体として安全」「承認可能」など、静的レビューの範囲を超えた保証をしない。指摘なしの場合も、確認した範囲に限定して表現する。
