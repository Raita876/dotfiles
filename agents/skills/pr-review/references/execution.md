# 実行方式の選択

レビューの観点・対象範囲・報告形式は共通にし、ツール呼び出しだけを現在の環境に合わせる。この skill 自体はツールやサブエージェントを登録しない。エージェント名やツール名を推測して呼び出さず、現在公開されているツールの説明と引数スキーマを確認する。

開始時に「使用する実行方式」「並列上限」「選択した観点」を伝える。サブエージェントの呼び出しは追加のモデル実行・費用を伴う。

## Pi + billion-context

`acp_delegate`、`acp_delegate_wait`、`acp_delegate_cancel` が利用できる場合に使う。

- `acp_delegate({ agent: "reviewer", cwd: <repo>, task: <自己完結した依頼>, async: true })` で既存の reviewer を起動する。`pr-test-analyzer` のような未登録の agent 名は渡さない。
- runId と観点の対応を記録する。`acp_delegate_wait` は結果を取得するときに使い、タイムアウトしたら繰り返しポーリングせず、他の結果の確認などを行って完了通知を待つ。
- 完了後は返された結果ファイルを読み取りツールで読む。要約通知だけで検証済みとはしない。
- 停止を求められたら走行中の runId を `acp_delegate_cancel` で止める。

## Claude Code / Codex / その他のネイティブ委譲

現在の環境にサブエージェントの起動・結果取得機能が公開されている場合に使う。CLI の種類だけで機能が利用可能だと判断しない。機能フラグ、設定、バージョンなどにより異なる。

- 公開された起動ツールのスキーマに従う。読み取り専用の reviewer / explorer 相当が実際に登録されていれば優先する。なければ利用可能な汎用 agent にレビュー専用の制約を渡す。編集用 agent を必要もなく選ばない。
- 観点ごとの専門指示、対象 repo・リビジョン・差分、規約、禁止事項、報告形式を起動時の依頼に明記する。会話の継承や自動読込には依存しない。
- 各実行 ID と観点を記録し、ツールに実装されている待機・結果取得で本文を確認する。同期ツールが独立した並列起動を提供しない場合は逐次実行とする。実行可能な上限が3件未満なら低い方に合わせる。
- 停止・終了機能が公開されていればそれを使う。停止を確認できない実行は「停止済み」と報告せず、ユーザーに残存状態を伝える。
- Pi の runId や結果ファイルの方式を他のツールに当てはめない。存在しない `reviewer` 役割や専用 agent 定義を要求しない。

## 委譲ツールがない場合

- 起動前に「この環境には利用可能な委譲ツールがないため、同一エージェントが観点別に逐次レビューする」と明示する。依頼が実行方式を指定していなければ、この方式で進めてよい。
- ユーザーが `parallel` や独立したサブエージェント検証を明示的に要求した場合は、勝手に単独レビューへ切り替えず、逐次実行でよいか確認する。
- 同じ差分を使い、選択した観点の指示を1つずつ適用する。最終報告で「単独・観点別の逐次レビュー」と記載し、独立した複数 agent の検証とは区別する。
- 委譲を実現するために `claude` / `codex` / `pi` の別 CLI をシェルから起動したり、拡張をインストールしたりしない。必要ならユーザーに環境設定を相談する。

途中で委譲に失敗した場合も、単独レビューで代替した観点と失敗した実行を明示する。実際のレビューが終わるまで完了扱いにしない。
