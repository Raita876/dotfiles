# comments: 説明と実装の整合

コメント、README、使用例、API の説明が対象リビジョンの実装と一致しているか調べる。

- 実際に存在しないコマンド、誤った引数・パス・既定値、必要条件の欠落を確認する。
- 変更後に古くなった前提、不変条件、公開契約、セキュリティや互換性の保証を確認する。
- コメントが「なぜ」を伝えているかをプロジェクト規約に照らして確認する。ただしコメントの追加自体を目的にしない。
- TODO を完了済みだと誤認させる説明や、既知の制限を隠す記述を探す。

ユーザーが実際に誤操作する、実装者が誤った前提を使うなど、具体的な影響を示す。表現の好みや文体だけでは指摘しない。文書内のコマンドを検証のために実行しない。
